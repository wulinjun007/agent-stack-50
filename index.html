能力调用管线

本站不是"又一个清单"：它的 PRD、视觉、QA 与部署就是用榜上工具的能力做出来的。七个层级，每层标明调用了哪些项目、产出了什么；状态分四种——已调用（本交付实际发生）、方案已写（工件已落盘 deploy/）、路线图、参照。

为什么可信

每次"调用"都留下工件：OpenSpec 四件套在 openspec/，部署工件在 deploy/，58 道门禁的逐条结果在 QA-报告.md。榜单里每个条目的"如何调用"也按同一种四状态口径标注——不把计划写成事实。

PRD（V1.0 · 2026-10-07）

规格驱动开发（SDD），按 OpenSpec 目录组织；本页为精炼版，全文见仓库 PRD.md ↗。

1 · 背景与问题

Agent 工具生态爆发带来三个痛点：榜单噪音大（上千条目按字母排序）、二手数据失真（过期 star、错误许可、无视仓库迁移）、只列不用（不回答"怎么调用"）。本站的位置：GitHub API 逐仓核验 + 三主线严格分组 + "本站就是用这 50 项的能力做出来的"调用示范。

2 · 用户与场景

用户场景站内动作

3 · 定位与原则

年鉴式工具栈榜单——冷静、可核验、可复现。五原则：真实数据（API 逐仓拉取并标注快照）、诚实呈现（停更项标注停更）、能力调用（每条目回答"本项目如何调用它"）、无 slop（hallmark 纪律 + 58 门禁）、零依赖交付（单文件、无构建、无追踪）。

数据口径

快照与核验

时间窗 2026-10-06/07。字段来源：GitHub REST API GET /repos/{owner}/{repo}（star / 主语言 / pushed_at / license 标签），63 个候选仓逐仓拉取。"最近推送"取 pushed_at（含任意分支），不代表发版时间。

许可核验

GitHub license API 对自定义许可一律返回 Other/NOASSERTION。本站对 13 个存疑仓库逐个抓取 LICENSE 文件头部人工核对，得到"MIT 核心 + EE 目录商业""修改版 Apache-2.0""Polyform Shield 双许可"等真实结论。标"宽松许可"= OSI 认可且无重大附加条款；其余商用前请逐条读对应仓库许可。
